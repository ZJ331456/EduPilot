# EduPilot v4.0 架构升级设计与实施文档

> **文档类型**: 技术架构设计方案 & 实施指南  
> **目标版本**: v4.0 (Cognitive Loop Edition)  
> **核心理念**: 从“被动检索回答”转向“主动规划与自反思教学”

-----

## 1\. 核心变革：为什么要升级？

现有的 v3.0 版本（6 Agent）是一个优秀的 RAG 系统，但作为“智能助教”存在以下局限：

1.  **缺乏自我纠错**: 生成了幻觉或解释不清时，直接推给用户。
2.  **缺乏数理/实时能力**: 纯文本 LLM 无法处理复杂计算或获取最新新闻。
3.  **缺乏教学闭环**: 只有“讲”，没有“测”和“路径规划”。

**v4.0 解决方案**:
我们将 Agent 扩展为 **10个**，并分为三个职能特种部队。核心引入 **Reviewer (反思/审核)** 机制，构建“草稿-审核-修改”的质量闭环。

## 3\. 🔄 核心工作流逻辑 (LangGraph 实现)

v4.0 的核心在于\*\*“反思环 (Reflection Loop)”\*\*。以下是新的状态流转逻辑。

### 3.1 状态定义 (State Schema)

```python
from typing import TypedDict, List, Annotated
import operator

class AgentState(TypedDict):
    # 输入输出
    messages: List[BaseMessage]
    user_query: str
    final_response: str
    
    # 流程控制
    intent: str
    plan_steps: List[str]
    revision_count: int  # 记录修改次数，防止死循环
    
    # 数据槽位
    retrieved_docs: List[Document]  # RAG结果
    tool_outputs: dict              # 工具运行结果(代码/搜索)
    curriculum_plan: dict           # 课程结构
    
    # 审核槽位
    draft_content: str              # 初稿
    critique: str                   # 批评意见
    is_satisfactory: bool           # 是否通过
    
    # 用户上下文
    user_profile: dict
```

### 3.2 关键流程代码逻辑

**1. Orchestrator (路由节点)**

```python
def orchestrator_node(state: AgentState):
    """决定下一步调用哪些工具 Agent"""
    intent = state["intent"]
    
    # 并发执行列表
    parallel_actions = []
    
    if "calculate" in intent or "current_news" in intent:
        parallel_actions.append("tool_specialist")
    if "learn_concept" in intent:
        parallel_actions.append("knowledge_retriever")
    if "structure_learning" in intent:
        parallel_actions.append("curriculum_designer")
        
    return {"next": parallel_actions} 
    # LangGraph 支持返回列表以并行执行
```

**2. Reviewer (审核节点 - 核心)**

```python
async def reviewer_node(state: AgentState):
    draft = state["draft_content"]
    user_level = state["user_profile"].get("level", "beginner")
    
    # 提示词：扮演严厉的教务长
    prompt = f"""
    作为 EduPilot 的质量审核员，请检查这篇教学草稿：
    {draft}
    
    用户水平: {user_level}
    
    检查标准：
    1. 准确性：是否有未经验证的事实？
    2. 教学性：解释是否过于晦涩？
    3. 结构：是否分点清晰？
    
    如果不合格，请给出具体修改意见，并标记状态为 REJECT。
    如果合格，标记为 APPROVE。
    """
    
    result = await llm.ainvoke(prompt)
    
    if "REJECT" in result.content and state["revision_count"] < 3:
        return {
            "is_satisfactory": False, 
            "critique": result.content,
            "revision_count": state["revision_count"] + 1
        }
    else:
        # 超过3次即使不完美也通过，避免死循环
        return {"is_satisfactory": True}
```

```python
workflow.add_edge("query_analyzer", "orchestrator")

# 动态扇出 (Fan-out) 到工具组
workflow.add_conditional_edges(
    "orchestrator",
    lambda x: x["next"]  # 返回 ["knowledge_retriever", "tool_specialist"]
)

# 汇聚 (Fan-in) 到写作
workflow.add_edge("knowledge_retriever", "draft_writer")
workflow.add_edge("tool_specialist", "draft_writer")

# 反思环 (Reflection Loop)
workflow.add_conditional_edges(
    "reviewer",
    lambda x: "draft_writer" if not x["is_satisfactory"] else "end"
)
```

## 4\. 实施步骤与技术细节

### 4.1 第一阶段：基础设施升级 (Week 1)

1.  **数据库迁移**:
      * 部署 **PostgreSQL**。创建 `users`, `sessions` 表。
      * 将原有的 JSON 用户画像迁移到 PG 的 `jsonb` 字段。
2.  **工具链集成**:
      * 申请 **Tavily API** (推荐用于 AI Search) 或 Google Serper。
      * 设置本地 Python 沙箱 (用于 `ToolSpecialist` 运行简单的数学/绘图代码)。

### 4.2 第二阶段：核心反思环实现 (Week 2)

1.  **拆分 Executor**:
      * 将原 `Executor` 的代码拆分为 `DraftWriter` (只负责写) 和 `Reviewer` (只负责评)。
2.  **实现 Reviewer Prompt**:
      * 调试 Prompt，确保它不会过于挑剔导致无限循环，也不会过于宽松。
3.  **LangGraph 重构**:
      * 按照 v4.0 的图结构重写 `main.py`。

### 4.3 第三阶段：高级 Agent 开发 (Week 3)

1.  **开发 CurriculumDesigner**:
      * 设计 Prompt 让其输出标准化的 JSON 树结构。
      * 前端 Vue 组件开发：使用 `D3.js` 或 `ECharts` 渲染思维导图。
2.  **开发 QuizMaster**:
      * 实现逻辑：`DraftWriter` 输出完成后，`QuizMaster` 根据内容生成 3 道单选题。
      * 前端：渲染答题卡组件。
